# Мой архив — pinch grid: сводный разбор v1–v15
Дата: 2026-10-08. Статус: **v3 — временный эталон движения**, НЕ готовое решение.

## Цель
iPhone Safari/WebKit, 3–10 колонок, жест управляет плотностью непрерывно; центральная фотография и локальная точка под пальцами остаются привязаны; HOLD без движения; reverse точно воспроизводим; отпускание без скачка; целые фото, без устойчивого двоения, пустот, диагональных куч. Рабочий fullscreen viewer не менять. VPS/production не трогать.

## Эталон и ограничения источников
- **v3** по пользовательской оценке «уже лучше»: непрерывный fractional-flow, плотное заполнение и плавное изменение размера, но фотографии **разрезаются между строками**. Сохраняем именно кинематику v3. Код v3 в текущем GitHub lab пока не обнаружен/не проверен: это описание наблюдавшегося поведения, не проверенная реконструкция реализации.
- Apple Photos — визуальный эталон, НЕ известная нам реализация. В пользовательской записи VID_20261008_161652.mp4 отмечены кратковременные нерегулярные/перекрывающиеся участки; из видеокадров нельзя достоверно вывести внутренний алгоритм.
- Проверки v11–v15 проводились на пользовательских записях; численные метрики collective solver ниже — сообщение Codex, а не независимая перепроверка исходного results.json.

## Collective constrained packing: отдельная ветка
Первый solver (по сообщению Codex) FAIL: на 5.5 — 68 пересекающихся пар, 13.6% пустот, скачок до canonical endpoint 324.39 px. Это отказ конкретного solver, не доказательство невозможности архитектуры. Codex продолжает исследование независимо.

## Причинная модель: почему v3 работала лучше
У регулярной row-major сетки на integer N строка состоит из N целых квадратов. При fractional density N+t «идеальный» размер квадрата w/(N+t) не позволяет заполнить ширину w целым числом равных квадратов без остатка. v3, по наблюдению, устраняла эту проблему, рассматривая ряд как непрерывную ленту и позволяя *визуальному фрагменту одной карточки* оказаться на следующей строке. Поэтому плавность достигается ценой нарушения атомарности карточки.

Попытки v10/v11 убрать разрыв только clipping/fade не обеспечивали **передачу собственности плитки** между строками; скрытая часть исчезала, оставляя пустоту. v4/v5/v7/v12 сохраняли атомарность, но совершали дискретную смену topology. v2/v8/v15 сохраняли атомарность и интерполировали позиции, но разные строки пересекались по диагонали. v6/v13/v14 показывали две копии одного ID и потеряли визуальную чистоту/якорь.

### Ключевой вопрос
Можно ли сохранить **непрерывную фазу fractional-flow v3** и одновременно рисовать каждый tile как единый объект? Это не то же, что линейно интерполировать позиции между двумя canonical grids. Если ответ нет при строгих равных квадратах и нулевых пустотах, нужно измерить минимальный локальный визуальный компромисс, а не ломать глобальную кинематику.

## Приоритетный план (сначала исследование, потом пользовательские тесты)
1. **Восстановить ТОЧНЫЙ исходный код v3** из прежних файлов/истории, если доступен. Не объявлять реконструкцию оригиналом.
2. Зафиксировать baseline на 5.0, 5.1, 5.5, 5.9, 6.0, HOLD, reverse, release, быстрый 5→8→5: снимки, координаты tile ID, фокус, долю разрезанных tile. Это **golden test**.
3. Сделать узкий эксперимент **seam ownership**: вычислять ту же fractional-flow координату/фазу, что v3, но в области перехода через строку показывать **одну целую карточку**. Протестировать три строго разделённых способа: (a) временное локальное перекрытие при передаче; (b) локальный свободный слот с движущимся gap; (c) краткая локальная маска/opacity только переходящей карточки, без копии ID. Для каждого показать tradeoff.
4. Не трогать поведение остальной сетки. HOLD и reverse должны быть функцией жестового progress, без таймеров; сохранение anchor: **ID + col + локальные fx/fy**, а не первая карточка ряда.
5. Автоматические проверки: число экземпляров ID (ровно 1), размер карточек (одинаковый), доля перекрытий, доля пустот, максимальный скачок координат при delta density 0.01, anchor drift, endpoint error. Важно: «ID один раз в массиве» недостаточно — видимая карточка не должна распадаться на два фрагмента.
6. Публиковать отдельный HTML только когда сравнительные кадры показывают улучшение относительно v3 без появления новых массовых дыр/куч. Если не улучшили, честно FAIL и оставить v3 эталоном.

## Принятое решение
**v3 — baseline для всех последующих сравнений.** Не заменять эталон более поздней версией только потому, что она новая. Сначала исправить **один** недостаток v3 — seam splitting, не потеряв плавность fractional-flow. Codex исследует packing параллельно, без вмешательства в эту ветку. Любая модификация только в GitHub lab, не в production.
